# ADR 0003 — Quan sát file USB và giới hạn dữ liệu

**Trạng thái đề xuất, chờ Owner duyệt.** Phạm vi D04, D07 và D08. F0 quyết định collector dựa trên phép đo. F1 chỉ triển khai theo kết quả F0 đã được duyệt. Xem [blueprint](../../BLUEPRINT.md).

## Phương án F0

- Dùng UDisks2 làm ứng viên quan sát volume/mount, đối chiếu udev/sysfs tới thiết bị cha, partition và HASH USBGuard. Dùng mountinfo khi cần định danh mount tại namespace quan sát. Kiểm mount ID, major/minor, filesystem, lifecycle generation và trường hợp nhiều partition, remount hoặc disconnect. Chỉ giữ scope cho volume được Agent xác nhận là allowed. [UDisks2 Filesystem](https://storaged.org/doc/udisks2-api/latest/gdbus-org.freedesktop.UDisks2.Filesystem.html)
- Thử Linux Audit với rule giới hạn vào mount và host roots đã cấu hình. Đo đầy đủ path, UID/AUID theo khả năng, executable, process generation và kết quả, cũng như giới hạn khi copy đi qua helper/process khác. Theo dõi số record mất, backlog, hiệu năng và khả năng gỡ riêng rule của thử nghiệm. Nếu không đủ evidence, thử fanotify adapter trong F0, đo coverage theo filesystem, queue overflow, file-handle support và hoạt động mmap. WatchService/inotify dùng được cho invalidation inventory. Tín hiệu thay đổi đơn lẻ không đủ kết luận hướng copy. [Linux Audit trên Ubuntu 24.04](https://manpages.ubuntu.com/manpages/noble/man8/auditctl.8.html) · [fanotify trên Ubuntu 24.04](https://manpages.ubuntu.com/manpages/noble/man7/fanotify.7.html)
- Native Ubuntu 24.04 trên máy hoặc VM có USB passthrough, FAT32 và exFAT tối thiểu. Dùng fixture biết trước hai path và kết quả. Chạy GNOME Files copy/paste và drag/drop, `cp`, `mv`, hai hướng, file đơn, nhiều file và thư mục. Ghi syscall path thực tế để bao phủ cả buffered và fast-copy. Với nhiều copy đồng thời, đối chiếu từng cặp source/destination và đánh dấu ambiguous khi correlation thiếu evidence. Negative/partial cases gồm đọc để xem, edit tại chỗ, rename cùng volume, cancel, collision, symlink và tháo USB giữa thao tác. Ghi tỉ lệ đủ evidence, false copy, unknown, mất event, overhead và attribution theo từng workflow. Đề xuất gate tối thiểu là quan sát được cả hai hướng trong từng workflow bắt buộc ở phạm vi test đã duyệt, và tập ca đọc/đổi tên/gián đoạn không bị báo là copy hoàn tất. Nếu hụt, trình Owner khoảng trống và phương án bổ sung controlled workflow trước F1.

## Contract và quyền dữ liệu đề xuất

- Pipeline có mount observer, inventory metadata, observation adapter, correlation, classification, outbox và ingestion scoped. Collector đặc quyền chỉ nhận cấu hình scope có kiểm, gửi sự kiện typed tới Agent qua IPC riêng có xác thực peer và quyền OS tối thiểu. Agent tiếp tục enforcement khi collector dừng. UI báo degraded/overflow và phần coverage thiếu.
- Inventory chỉ đọc metadata trong volume đã mount và allow. Bounds theo số entry, depth, thời gian và byte payload. Resolve path trong volume đã xác minh và ngăn symlink hoặc mount crossing ra ngoài scope. Scan có snapshot/sequence, pagination và báo kết quả partial khi quyền, mount hoặc quota thay đổi.
- Observation biểu diễn hoạt động đã thấy và trạng thái cuối theo chứng cứ. Copy inference yêu cầu tương quan process/actor, window, source/destination và dấu hiệu kết thúc phù hợp. Dùng `HOST_TO_USB`, `USB_TO_HOST`, `UNKNOWN`, `NOT_APPLICABLE` theo ngữ nghĩa blueprint. Giữ `OBSERVED`, `INFERRED`, `UNKNOWN` và nullable paths. Sau revoke/unmount hoặc stop giữa chừng, dùng interrupted hay unknown theo evidence. Event ID, workspace/endpoint, volume/mount generation, process identity cần thiết, observation time, operation, status và gap flags theo typed contract.
- Gửi metadata tối thiểu. Chỉ thu path USB và host endpoint thuộc root được phép. Đường dẫn ngoài scope được redacted hoặc để trống, executable identity cần cho attribution, tránh command line và file content. Agent xác minh mount/path thực tế. Server lấy scope từ credential, kiểm schema, size, encoding và ranh giới cấu hình áp dụng cho endpoint, rồi lưu theo workspace. Chỉ principal thuộc workspace được đọc hoặc export. Đề xuất tắt export mặc định, ghi audit khi bật hoặc export.
- Dùng durable outbox cho file activity với quota riêng để backlog file không tranh budget sự kiện bảo vệ USB. Đề xuất pilot 64 MiB hoặc 10.000 file events mỗi endpoint, ngưỡng nào tới trước. Khi quá quota, báo gap counters và thời điểm coverage mất, tiếp tục enforcement. Dùng gap record nhỏ dành riêng và coverage checkpoint tăng đơn điệu theo collector generation. Central chỉ hiển thị healthy với checkpoint còn tươi và có bằng chứng liên tục. Checkpoint stale, bị gián đoạn hoặc generation mới chưa đối chiếu hiển thị UNKNOWN cho khoảng thời gian thiếu. Khi reconnect, dùng gap marker hoặc checkpoint tiếp theo để khoanh vùng khoảng trống. Server đề xuất retention 7 ngày và tối đa 100.000 file events/workspace ở pilot, tính theo thời điểm nhận và có audit prune. Kiểm disk-full kết hợp mất LAN và restart, quota, crash durability/idempotency và hiệu năng tại F0/F1, điều chỉnh trước chốt. SQLite hoặc storage khác chỉ chọn nếu filesystem spool không đạt durability, recovery hoặc throughput đã duyệt. [Outbox hiện hành](../../client-agent/src/main/java/com/group/usbshield/agent/outbox/OutboxSpoolService.java)

Owner duyệt host roots, quota/retention mặc định, quyền export, gate định lượng và lựa chọn collector sau F0. F1 gate liên quan E13–E16, gồm replay offline/dedup đúng workspace, bounded inventory, scope escape và báo coverage gap.

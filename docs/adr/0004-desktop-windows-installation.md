# ADR 0004 — Central Desktop và cài đặt Windows

**Trạng thái.** P2 dùng JavaFX và một launcher Windows cho các dịch vụ đã provision. Toolchain installer phát hành và lifecycle nâng cấp vẫn thuộc R1. Phạm vi D06, D07 và vận hành LAN của D03. [Blueprint](../../BLUEPRINT.md)

## Bối cảnh

Baseline phát hành JAR Spring Boot với frontend build bằng Node/Vite và profile `with-frontend`. Nginx và PostgreSQL được cấu hình riêng. Luồng Windows build/release hiện tại tạo artifact và checksum, còn Ubuntu cài theo service unit. P2 cần parity Desktop và loại bỏ frontend atomically. R1 đủ điều kiện phát hành khi installer và upgrade đã được test native. [Server POM](../../admin-server/pom.xml) · [Build release](../../admin-server/build-release.ps1) · [Nginx mẫu](../../packaging/nginx/usbshield-https-acl.conf.example) · [Agent unit](../../packaging/systemd/usbshield-agent.service)

## Runtime đề xuất

- Dùng module `admin-desktop` với JavaFX tương thích JDK 21, FXML/CSS và client HTTPS typed. Controller/view model giữ UI. Use case application điều phối request, timeout, cancel và pagination ngoài FX thread. Đóng gói runtime Windows cho app, giữ Spring Boot/JPA/PostgreSQL/Flyway và Agent Spring Boot non-web. Giữ notifier process và entry point hiện có trong `client-agent` cho đến khi có lý do tách module.
- Desktop chạy dưới user Windows trên Central host, giữ session/CSRF qua TLS. Đề xuất dùng cùng tên DNS SAN đã provision, resolve loopback tại Central và LAN IP từ Ubuntu. Tách listener/routing để Admin API chỉ truy cập từ loopback, LAN listener chỉ mở Agent API trên 443 với ACL phù hợp. Backend và PostgreSQL bind loopback, trust CA/SAN được provision trước, native acceptance kiểm hostname/CA sai, LAN source mapping và không cần Internet. UI tách desired/applied/actual và offline/stale theo ADR 0002.
- P2 lập bảng parity cho login/logout, dashboard, endpoints/health, devices, whitelist và USB events. Xóa React, static SPA, Maven copy profile, Node build hooks và release/browser references trong cùng change sau khi API/Desktop tests thay thế coverage UI hồi quy. Giữ các test contract tích hợp có ích hoặc chuyển chúng sang consumer phù hợp. Inventory và file activity theo slice F1.
- Phân tách Windows service identity cho DB, backend và Nginx adapter theo dữ liệu cần đọc, tránh quyền local admin lúc chạy. Secret/PKI và DB data vào thư mục dữ liệu bảo vệ, binary vào thư mục ứng dụng. TLS private key chỉ proxy/service identity đã cấp, app chỉ cần CA. Dùng log rotation và health checks để launcher báo service/DB/TLS lỗi chính xác.

## Bộ cài và lifecycle

Phương án ưu tiên thử một bundle Windows signed có thể điều phối runtime Desktop, backend, PostgreSQL và Nginx, với package app image bằng `jpackage` và nhà điều phối MSI/EXE riêng. MSI ServiceInstall/ServiceControl cung cấp lifecycle cho service tương thích SCM. Nginx Windows là console application theo upstream, nên cần đánh giá wrapper đã review hoặc quản lý process bằng cơ chế Windows phù hợp. Kiểm license, provenance, khả năng repair/uninstall, service account và support Windows target trước khi chọn wrapper và toolchain. Phương án launcher có kiểm quyền và thành phần cài kèm là fallback nếu bundle MSI/EXE không đạt gate. Chốt chính xác toolchain version và phụ thuộc trước build phát hành. [Oracle jpackage](https://docs.oracle.com/en/java/javase/21/jpackage/packaging-overview.html) · [MSI ServiceInstall](https://learn.microsoft.com/en-us/windows/win32/msi/serviceinstall-table) · [MSI ServiceControl](https://learn.microsoft.com/en-us/windows/win32/msi/servicecontrol-table) · [Nginx Windows](https://nginx.org/en/docs/windows.html)

1. **Preflight và provision.** Kiểm Windows target, kiến trúc, quyền cài, dung lượng, ports, DNS/CA/SAN, IP/ACL, service đã tồn tại và dữ liệu cần giữ. Kiểm signature/hash, ghi manifest từ artifact provenance. Bootstrap DB role và TLS theo config đã duyệt, cấp credential Admin theo ADR 0001.
2. **Start và verification.** Khởi động DB rồi bật backend/Flyway, xác minh readiness. Bật proxy và chạy TLS/ACL probes trước khi mở Desktop. Kiểm Desktop trên loopback, Agent từ LAN và no Internet khi LAN còn. Từ máy LAN Client, xác minh Admin/auth route bị từ chối và cổng backend/DB không truy cập được. Kiểm CA hoặc SAN sai với Desktop và Agent đều fail closed, không fallback sang HTTP. Fail ở step nào báo trạng thái step đó và giữ dữ liệu để phục hồi. Không đưa credential vào logs, args hoặc status output.
3. **Upgrade và uninstall.** Đối chiếu version/protocol, backup DB/config đã test restore, drain hoặc bảo toàn outbox endpoint. Upgrade chạy migrations đã duyệt, có rollback trước khi nhận ghi mới. Sau DB migration có ghi dữ liệu cần forward repair hoặc restore đã duyệt. Uninstall gỡ service/app và giữ DB/config theo mặc định. Xóa dữ liệu cần quyết định riêng được hiển thị và ghi nhận. Thu hồi firewall/TLS material theo tài nguyên thuộc installer, giữ tài nguyên ngoài scope cài.

## Gate P2/R1 và điểm cần duyệt

Launcher P2 nằm trong một gói Windows cùng API JAR, JavaFX app image và Java runtime. Desktop dùng IP SAN `127.0.0.1` để kết nối trực tiếp đến listener loopback, Nginx dùng DNS SAN riêng cho Agent LAN. Cách này bỏ DNS khỏi đường xác thực Desktop. Không thay đổi quy trình provision PKI, database và tài khoản Windows service. [Hướng dẫn IT](../IT_SETUP_GUIDE.md)

P2 cần build Windows/JavaFX và parity API/Desktop thật với no-Internet LAN. R1 cần install/upgrade/restart/uninstall từ máy sạch, lỗi cố ý ở từng bước, tiếp tục sau reboot, quyền service, TLS invalid CA/SAN, health/error rõ và không mất dữ liệu. Test Ubuntu `.deb` riêng theo packaging hiện hành. Liên quan E04, E12 và E17. Owner duyệt Windows target, nguồn phân phối artifact/components, PKI owner, lifecycle toolchain và quy tắc rollback trước khi build installer phát hành.

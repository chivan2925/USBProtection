## Executing and maintaining this inventory

From repository root, use JDK 21+, Maven, Node/npm, Windows Chrome/Edge and Git Bash. Build frontend before `-Pwith-frontend`. Browser suites share ports/runtime assumptions and must run sequentially with isolated temporary H2, QA-only credentials and browser profiles. Offline/cache failure is an execution limitation; retain its log and successful retry separately.

```powershell
mvn -B -f client-agent/pom.xml clean package
powershell -NoProfile -ExecutionPolicy Bypass -File packaging/tests/verify-week3-windows.ps1 -CheckBuiltJar
powershell -NoProfile -ExecutionPolicy Bypass -File packaging/tests/test-staging-verifier.ps1
bash -n packaging/scripts/build-deb.sh
bash -n packaging/agent-deb/DEBIAN/postinst
bash -n packaging/agent-deb/DEBIAN/prerm
bash -n packaging/desktop/usbshield-notifier-launcher.sh
Push-Location frontend
npm ci
npm run lint
npm test
npm run build
Pop-Location
mvn -B -f admin-server/pom.xml -Pwith-frontend clean package
Push-Location frontend
npm run test:browser
npm run test:live
npm run test:browser:live
node --test tests/m4_policy_live.test.mjs
Pop-Location
```

The checked-in browser suites use Vite/proxy. Separate JAR-origin browser evidence is needed to claim that delivery mode. A unit-test count is the total of its suite, not one count per mapped requirement. Windows native mocks never close physical USB/Ubuntu/GUI scenarios.

For each run, attach the evidence path, exact source/build manifest and tested SHA, then replace `Not run`/`NOT EXECUTED` only for assertions actually covered. Retain failed attempts and explain environment problems versus product failures. Mark remaining cases deferred. Do not edit Week 1–3 reports to make their old results look like a new run.
